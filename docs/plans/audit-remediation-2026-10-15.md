## 实施约束

1. 一项一项推进：先将报告的失败现象改写为期望安全行为的正式回归用例，记录 FAIL；再最小修复，记录 PASS；最后执行相邻回归。共享同一段实现的条目可以同批修改，但每个 ID 必须有独立验收记录。
2. 不把外部“成功复现缺陷”的断言当成修复后的通过标准。基线已通过的 633 项测试不能替代新增的反例测试。
3. 仅使用合成地址、临时账号目录、内存凭据后端、本地协议服务和受控并发闸门；不读取、发送、标记、移动、删除真实邮件，不修改真实账号、凭据或客户端配置。
4. QQ/网易直连、Gmail 必须走代理；TLS 证书校验、端点绑定、附件目录约束、私有会话保护和现有预览幂等保护均为必须保留的回归边界。账号写入 MCP 工具保持不存在。
5. 本 PR 不调整本机 40 工具白名单，也不执行报告中的临时部署建议。后续部署、正式发布、命名空间变更、真实服务商验证分别经过维护者授权。
6. 不通过降低审计阈值、删除安全用例、无限重试或扩大白名单来使检查“通过”。不提交秘密、邮件内容、构建产物、原始本机日志或未审查的复现脚本。
7. **ENG-01 延续此前开发依赖暂不处理的范围约束。**本计划完整登记方案和验收，但实施该项前须由维护者明确决定是否解除此前排除；本 PR 不更新依赖或关闭全量 audit 门禁。ENG-04 的正式包名、MCP 命名空间和发布权限同样留待维护者决定。

### 阶段 A：先关闭安全和数据完整性缺口

- [x] **A0 — SA-08（P1）：网易全局搜索分页兼容。**本批已实现并通过上述验收，缺 UIDNEXT 不再提前报错，实际 UID 搜索结果建立有界分页起点；与 SA-04 独立。未修改状态字段或扩展统一错误框架，也未重跑真实邮箱或处理其他账号 timeout。
- [ ] **A1 — SEC-01 已完成；BUG-SEC-06 待处理：统一 API 信任边界。**本批会话鉴权和路由已共用匹配规则，大小写/尾斜杠、同源、Host、Sec-Fetch-Site 和 no-store 回归通过。严格 HTTP 输入及持久化候选 schema 属于 BUG-SEC-06，尚未实施，须单独验收非法字段在任何文件或凭据写入前被拒绝。
- [ ] **A2 — SEC-02：统一安全 IMAP 连接构造。**隐式 TLS 与必须成功的 STARTTLS 明确建模；服务器不广告 STARTTLS、返回 NO 或证书失败时，认证字节发送量必须为零。connect、authenticateOnly、testConnection 共用策略；本地 bridge 明文例外若保留，须显式选择并限于 loopback。
- [ ] **A3 — MAIL-01：统一邮箱选择锁。**消除业务裸 mailboxOpen，将状态读取和 mailbox 快照放入同一个持锁方法。用闸门证明 folder_status(B) 不能把持锁操作 A 的 UID 命令切到 B；覆盖读取、旗标、移动和删除。
- [ ] **A4 — MAIL-09a、MAIL-09b、MAIL-08：精确移动/删除能力与结果。**在发送破坏性命令前核验原生 MOVE、UIDPLUS 或依赖已验证的等效 rev2 能力。无 MOVE 的流程只有 COPY 明确成功后才允许精确删除；不允许普通全邮箱 EXPUNGE 回退。false/undefined/throw 不能增加 deleted 计数。UID7 的确认不得影响已带 Deleted 的 UID9。不能依靠事后检查撤回已经发生的删除。
- [ ] **A5 — MAIL-02：封闭所有 PDF 解析入口。**下载和正文附件预览统一走受限子进程，沿用 256 KiB、20 页、5 秒、文本/并发预算；不退回主进程解析。超限二进制可按策略保存，预览返回可解释原因；测试其他 MCP 调用仍可响应。
- [ ] **A6 — SA-01：账号版本与 IMAP 缓存失效。**按连接关键字段计算稳定版本/指纹，每个操作比较最新配置；变化时关闭旧连接并仅用最新配置重连。显示名称变化不必重连；身份变更使相关发送/删除预览失效。该版本机制作为 B2/B4 和后续可信确认的基础。
- [ ] **A7 — MAIL-07：域名操作的精确候选集合。**IMAP FROM 只能粗筛，随后解析真实发件地址并核对域名；明确子域名策略。相似域、显示名包含目标域、目标域只在地址其他部分出现时不得进入冻结清单。先验证集合，再沿用 A3/A4 的锁、能力门禁和预览确认。

**A 放行门槛：**上述每个 ID 有独立 FAIL→PASS 记录；零明文凭据降级、零 COPY 失败后的删除、零越出确认 UID 的 EXPUNGE、零并发错邮箱操作；PDF 边界在下载入口也生效。未复现的条目记录复现环境和结论，不静默删除。

### 阶段 B：正确性、事务和恢复

- [ ] **B1 — SEC-03、BUG-SEC-04：统一凭据生命周期事务。**新增、修复、删除遵守同一跨进程协议；人工输入和浏览器授权可在锁外，提交时锁内重验账号版本和 target。CLI 注册也必须验证登录后才报告成功。repair/remove 交错后不得恢复孤儿秘密，失败的旧修复不得覆盖已提交的新凭据。
- [ ] **B2 — SA-02、SA-03：完整连接生命周期。**同账号建立/重连采用 single-flight；在认证前登记取消 epoch/AbortController，贯穿 token、握手和缓存提交。认证中取消后不得继续拨号；每个 await 后重验取消与账号版本。覆盖 10 个并发首次访问、失败后重试、移除和总搜索截止时间。
- [ ] **B3 — BUG-SEC-05、BUG-SEC-A1：截止时间及清理。**OAuth 截止覆盖 fetch、成功/错误响应体读取与解析，响应体有总字节上限，drip-feed 不能延期。所有临时 IMAP 客户端在 finally 中 logout/close；清理异常不覆盖首个失败，设置服务 stop 清理自身连接与监听器。
- [ ] **B4 — MAIL-12：SMTP 配置和令牌生命周期。**复用 A6 的账号版本失效机制；发送前取得有效 token，或使用带过期语义的 provision 回调。测试 token 到期、密码/服务器变更和清理。只在可证明尚未提交 DATA 的认证失败时重建；已接受或结果不明时禁止自动重发。
- [ ] **B5 — MAIL-03、MAIL-10：单一 MIME 与真实提交回执。**冻结并复用同一份 MIME/Message-ID 用于发送与 Sent 副本，核对 envelope/BCC 行为，不能因原始 MIME 漏掉信封收件人。保留 accepted/rejected/rejectedErrors，部分接受给出明确回执；只为被拒收地址生成独立新预览，不向已接受者自动重发。SMTP 接受不能称为最终送达。
- [ ] **B6 — MAIL-04、MAIL-05：地址模型和邮件多视图。**保留 Reply-To、完整 To/Cc，reply-all 排除自身并去重；HTML 和 text 转发均含用户附言及原始邮件信息，正确处理转义与附件 CID。用真实 MIME 金样覆盖多收件人、中文显示名、内联图片及无 text 的 HTML 原信。
- [ ] **B7 — MAIL-11：稳定附件身份。**用 partId/唯一索引而非文件名定位，转发一次读取并物化原附件；绑定消息定位及 UIDVALIDITY。两个同名附件必须保留各自字节哈希、顺序和内联语义；不能只断言文件名正确。
- [ ] **B8 — SA-04、SA-05、MAIL-06：统一检索与统计语义。**发现失败的账号进入明确的有限重试/游标契约；搜索参数共用严格日期、正整数和上限约束；未读使用命名邮箱 STATUS 统计，异常返回 unavailable/error，不能用 0 代替失败。覆盖超过 5000 封未读、首轮发现失败后仅靠续查恢复、闰年和逆向日期范围。
- [ ] **B9 — SA-07：账号存储读取一致性。**ENOENT 明确为空配置，其他损坏/不可读状态明确拒绝依赖旧权限继续操作；候选 Map 先解析校验再替换。删除文件后查询不能返回旧账号，随后新增只能包含新账号，恢复合法文件后能恢复正常读取。
- [ ] **B10 — ENG-02、ENG-03：安装配置的安全写入。**仅 ENOENT 可以初始化；坏 JSON、权限或结构错误保留原文件；通过候选校验后备份并原子替换，保留其他服务。同名条目由用户选择。执行路径基于安装模块位置，不依赖 cwd；在临时客户端配置和任意 cwd 下完成 stdio 初始化验收。
- [ ] **B11 — ENG-01：开发依赖，先确认范围。**保留原排除决定，待维护者授权后再更新相关 Vitest 包及锁文件，删除或替代未使用 nodemon 链。修复版本在实施日重新查官方公告，不盲目 audit fix --force，也不降门禁。恢复开发、构建、测试、打包及生产/全量审计检查。
