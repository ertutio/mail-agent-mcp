## 持续执行循环

**选择 → 最小实现 → 定点验收 → 保存/PR → 继续下一就绪项。**

- 实现前先建立能暴露当前缺陷的受控反例，再做最小修复，核对工具 schema、服务、调用者、文档、状态与失败/取消路径；纯文档用静态检查，不制造镜像实现的测试。
- 相邻回归用于开发反馈；稳定集成点按 T35、AGENTS 和[验收约定](../acceptance.md)执行必要检查。区分产品、fixture、工具输入、依赖公告和运行环境故障，不能靠跳过断言、真实账户试发或关闭门禁得到绿色。
- 每个行为单元更新进度的提交/分支、用例、FAIL→PASS、未测项及一条具体 next_action，再提交可恢复代码。适合评审时开 PR；一个检查点可包含多个小提交/PR。
- 保存或 PR 开出后立刻回到队列。等待评审时先做独立工作；需要未合并契约时可在明确父 PR 的分支继续并记录堆叠关系，合并/基准变化后重验受影响范围。共享契约不确定只暂停依赖路径。
- 相同文件默认一个写入者；共享文件冲突不是额外技术依赖。工具/技能/代理不可用时采用已验证的可用路径，记录缺口，不因一个角色缺失自动停下所有独立工作。

### 保存点与结束条件

只有当前核心实现、逐项适用断言和必要评审都有证据，并且原编号都有明确结论，才可称该核心范围完成。T33 未获本次授权的扩展维护及 T34/T36 等尚待维护者决定或授权的范围列为 `awaiting_human`，不写 PASS，也不擅自扩入或取消；全路线无剩余条件时才标总任务 `complete`。

当前回合仅在以下情况结束：总完成条件满足；用户要求暂停/改范围；宿主额度/上下文/工具硬中断；或者所有就绪工作均已处理，只剩真实权限、设备、产品/共享契约决定等外部阻塞。先落盘 next_action、准确解除条件、未提交改动与运行中检查，再报告；不能因为完成 T01 或达到一个检查点就等待一句泛化的“继续”。

同一卡点累计保留目标、假设、修改及验证；两次针对性修正和有效验证仍不通过，或下一步要改变关键保护机制而依据不足时，先寻求独立只读判断。能力不可用则保留现场，推进独立工作。采纳后的定向修正仍失败，等待维护者对该卡点明确决定；换任务名/代理不重置计数，工具/权限未形成结论则如实记待验证。

## T01：MAIL-01，文件夹状态读取遵守同一邮箱锁

**目标**：同一账户并发 `imap_folder_status(B)` 时，不能把持锁操作 A 的 UID 命令切换到 B；状态返回也不能混合两个时点/邮箱的元数据。技术前置：无。建议从最新 main 的合适隔离工作树领取，保留任何现有脏改；无需复用旧计划分支继续堆提交。

**证据**：当前 `folder-tools.ts:55-61` 调 `getFolderStatus` 后调 `selectFolder`；`imap-service.ts:368-370` 裸 `mailboxOpen`。2026-10-17 历史执行的合成 gate 使 INBOX/[7] 的 `bulkDelete` 最终在 Archive 执行 mocked `messageMove`，仍报告 deleted=1（[probe-results.json](https://github.com/ertutio/mail-agent-mcp/blob/eee1daf88b52d4969f96c117dc93219b6dd5c7f3/docs/analysis/mail-mcp-20261017/probe-results.json)）。见行为链 E04/E05。该观察不涉及真实邮件。

**建议文件所有权**：一个实现者拥有 `src/services/imap-service.ts`、`src/tools/folder-tools.ts`、`tests/folder-tools-status.test.ts` 及一个对应的并发回归测试文件；按接口影响更新直接调用者测试。若确需扩大生产文件或改变共享约定，先交回主代理说明。不要为凑文件数新建测试模块，能清楚放入现有相邻套件就复用。

**实现契约**：

- 提供同一 folder lock 内的状态/旗标快照读取，或等价地让所有业务 SELECT 遵守该锁协议。保持 STATUS 的 counts 语义及现有 `uidvalidity/uidnext/flags/permanentFlags/customKeywords` 外形。
- 快照是稳定值，不把释放锁后仍变化的 `client.mailbox` 引用返回给 handler。异常、取消/关闭及读取失败最终均释放取得的锁。
- 逐一核对 `selectFolder/mailboxOpen` 的生产调用者；UID 读、旗标、移动、删除与状态读取共享协议。用程序/测试核对，不扩展为连接池重构。

**独立验收**：先在当前实现记录受控并发反例 FAIL，再以相同 gate 验证 B 等待 A 释放且 UID 命令仍作用 A。至少覆盖 A 的读取、旗标、移动、删除，并保留双邮箱同 UID/不同 UIDVALIDITY；状态读取失败后队列可继续、锁准确释放。完整状态字段与既有 counts/Set 序列化回归通过。测试应调用实际 ImapService 和 handler，避免只断言某个新 helper 被调用。

**开发检查**：定点运行上述并发/状态套件及受影响的 guarded-delete/move 邻接回归；类型检查用于验证接口。输入未变且已有有效成功证据直接复用。稳定合并验收按 T35 与当前仓库要求执行，不在每次 helper 调整后全量重跑。T01 不包含 TLS、账号 revision、MOVE/UIDPLUS 能力、PDF、依赖更新或部署。保存本项证据及进度后回到持续执行循环，默认检查下一就绪项 T02。

### 依赖与文件冲突

真实依赖主链为 `T07 → T11 → T12 → T14 → T15`，预览 T13 从 T11/T12 分出；T17 从 T09/T11 分出，T20 依赖 T11/T17；游标 T26 从 T11 分出，发现恢复 T27 在其后。其他项不存在因“同改一个文件”而强设的技术前置。修正应保留尚未接入消费者的兼容性，契约批不冒称整个缺陷关闭。

`imap-service.ts` 被 T01–T05/T12/T14/T15/T18/T25/T29/T30 等共享；`email-tools.ts` 被 T06/T28/T30 等共享；账户 manager/credentials 被 T07–T11/T17 共享；SMTP/safe-send 被 T13/T20–T24 共享。**这些是文件所有权冲突，默认串行一个写入者**。若临近实现确需分工，主代理先定接口与不相交文件。没有理由同时在同文件上启动多个执行代理。

T03/T04/T05 各自可独立回归，但在安全删除集成点三者和 T01 必须一起验收；单个返回值修复不能宣布危险回退已关闭。T21/T22/T30 同理分别负责 SMTP 接受、MIME 一致性、IMAP APPEND 完成，不能互相替代。
